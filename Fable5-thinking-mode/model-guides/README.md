# model-guides · 分档操作手册

给三个能力档位的模型各一份操作手册，目标只有一个：让接手 Jarvis-Workshop 的
任何模型**第一次出手就像老手**。手册内容是工作区的事实、规则、地雷和验收标准，
按档位重新校准了信任范围和表达方式——同一条规则，对 Opus 是"判断依据"，
对 Sonnet 是"执行边界"，对 9B 是"白名单之外一律禁止"。

## 怎么用

- 会话开始时，把对应档位的手册**整份**放进上下文（粘贴，或在目标仓库的
  CLAUDE.md 里用 `@` 引用本文件路径）。
- 加载顺序：工作区根目录 `AGENTS.md` → 本手册 → 目标仓库的设计文档
  （手册第 2 节会告诉模型去读哪些）。
- `local-9b.md` 特殊：它假设模型**没有工具、没有可靠先验知识**，一切靠
  操作者投喂。它必须全文贴入（控制在约 1.5k tokens），并且文末附有给
  操作者的使用守则。

## 选档

| 文件 | 适用对象 | 信任模型 | 核心机制 |
|------|---------|---------|---------|
| [opus.md](opus.md) | Opus 级（准前沿） | 工程决策放权，仅设两道硬门（物理门、契约门） | 判断力转移：告诉它"这里什么不一样" |
| [sonnet.md](sonnet.md) | Sonnet 级（强执行器） | 按谱执行 | DECIDE / PROPOSE / STOP 三段边界 + 分任务菜谱 |
| [local-9b.md](local-9b.md) | ≤9B 本地小模型 | 白名单任务，其余一律 `ESCALATE` | 只用上下文里的文本；字面输出格式；操作者守则 |

## 维护

- **规则失效就删**——过时的规则比没有规则更糟；每份手册头部都写了这一条。
- learnings 笔记里稳定下来的 general rule，升格进对应档位的手册。
- 三份手册共享同一套工作区事实（各自的 "Workspace map" 一节）。**事实变了要
  三处同步改**；行为规则则各档独立。
- 大改后用一个新会话冷启动测试：只喂手册 + 一个真实任务，看模型是否还会
  踩已写明的地雷。
