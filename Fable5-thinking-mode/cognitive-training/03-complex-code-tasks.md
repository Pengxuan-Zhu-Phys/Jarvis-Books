# 03 · 专题：快而准地拿下复杂代码任务

> 这是一份**工作时打开**的操作手册：接到任务照着走。走过五次之后你就
> 不需要它了——那正是目的（五步法第 5 步：固化成本能）。

## 1. 出手前协议（10 分钟，一张卡）

动手之前填完这张卡。填不出某一格，说明该去问人或去侦察，**而不是开写**。

```markdown
## 任务卡：<一句话任务名>                          日期：

**交付物类型**：评估 / 改动 / 文档 / 设计   （四选一，选错全盘皆输）
**完成态**（可检查的验收标准，1–3 条）：
1.
**明确不做**（边界，至少 1 条）：
-
**需求主人**：<人名>（这任务谁要的？他真正想达成什么？）
**不可逆动作清单**（本任务会碰到的：删数据？改接口？动物理输出？）：
-
**最危险假设**（哪个假设若不成立，方案作废？验证它的最小实验是？）：
-
**验证方式**（哪条命令、哪个参考点，证明"完成态"达成？）：
-
```

各栏的填写要领：

- **交付物类型**：对方在描述问题 → 他要的是你的**判断**，先别改代码。
  拿不准就问一句"你是想让我先评估还是直接修"，这一句话的成本远低于
  做错方向的半天。
- **完成态**：必须包含验证方式能检查的谓词。"更快"不合格；"参考点
  扫描墙钟时间降低 ≥30%，物理输出与基线 diff 为空"合格。
- **需求主人**：五步法第 1 步的落地。写不出人名的需求，先去找到人名。
- **最危险假设**：这一格是整张卡的心脏，见下节。

## 2. 分解模式库

### 模式 1 · 风险前置（先杀最危险假设）

默认的任务排序是"从简单的开始热身"——错。正确排序是**从整个方案的
承重假设开始**：

> 例：给 Jarvis-HEP-v2 接一个新的外部计算器。承重假设是"它的输出能在
> 我们的超时预算内解析"。那第一件事不是设计接口，而是花两小时写一个
> 脏脚本调它一次、量一次。假设死了，方案死在第 2 小时而不是第 2 周。

一次性验证脚本（spike）的纪律：**写完就删**。它的交付物是"知识"，不是
代码；留下来它会腐烂成"看起来能用的东西"。

### 模式 2 · 垂直切片优先于水平分层

- 水平分层（先把数据层全做完，再做逻辑层，再做接口层）：每层做完都
  无法验证，集成风险全部堆在最后。
- 垂直切片（先打通一条最窄的端到端路径，再横向加宽）：第一天就有一个
  能跑通的"细管道"，之后每一步都是在**常绿系统**上加宽。

> 例：新采样器接入。切片版第一里程碑："固定返回同一个点的假采样器接入
> 全流程，扫描能跑完，输出格式正确"。物理上无意义，工程上千金——所有
> 接口问题在最简单的实现下暴露。

### 模式 3 · 绞杀式替换（strangler）

改造在用的模块时：新旧并存 → 流量逐步切到新的 → 旧的萎缩 → 删除。
永远不做"大爆炸式替换"（一次性删旧换新）——那等于把所有回滚点亲手
烧掉。判据：**替换过程中的任何一天，系统都能工作、都能回退。**

### 模式 4 · 里程碑写法（状态，不是活动）

| ❌ 活动式 | ✅ 状态式 |
|----------|----------|
| "重构配置解析" | "新解析器上线，`Workshop/YAMLs/` 下所有现存配置解析结果与旧版逐字节一致" |
| "加测试" | "采样器模块的失败路径（空先验、越界、NaN 似然）各有一个测试，全绿" |
| "对接 Agent" | "`hep_*` 工具签名冻结并写进设计文档，双方各有一个通过的合同测试" |

状态式的检验标准：**一个不了解过程的人，能独立判断这个里程碑到没到。**

## 3. 执行期三纪律

1. **常绿**：步与步之间测试通过、能构建。红着过夜 = 给明天的自己埋雷。
2. **单变量**：定位因果时一次只动一处。重构和行为修改永不同一个提交。
3. **证据**：每个"完成"配上运行输出。给自己也一样——尤其给自己。

## 4. 完整 worked example：给 Jarvis-HEP-v2 加一个嵌套采样器

**第 0 步 · 任务卡（节选）**

- 交付物类型：改动
- 完成态：(a) 参考模型上嵌套采样与现有 MCMC 的后验一致（KS 检验通过）；
  (b) 全套测试绿；(c) `YAML_REFERENCE_2.0.md` 有配置条目和可运行示例。
- 明确不做：不改现有采样器的任何行为；不动似然层。
- 需求主人：我自己——目的是处理多峰后验。**质疑一下**：现有问题真的
  多峰吗？有没有一次真实扫描的证据？→ 找出一次卡住的扫描作为动机存档。
  （如果找不到：需求可能是"以为会需要"，挂起任务。这一步救过的时间
  比所有优化加起来都多。）
- 最危险假设：外部嵌套采样库的调用模式（回调式）能塞进我们的
  point-by-point 执行模型。验证：半天 spike，用假似然跑通一次。
- 验证方式：`python -m pytest` + 参考点扫描对比脚本。

**第 1 步 · 删除**：要不要自己实现算法？不要——用成熟库。要不要支持
库的全部功能？不要——只暴露 3 个参数（live points、精度、种子），其余
用默认值。**每少暴露一个参数，就少一个要文档化、要测试、要永远维护的
承诺。**

**第 2 步 · 里程碑序列（每个都是可验证状态）**

| # | 状态 | 验证 |
|---|------|------|
| M1 | spike 证实回调模式可行（然后删掉 spike） | 假似然跑通一次 |
| M2 | 假采样器（固定点）接入全流程，测试绿 | 全套 pytest |
| M3 | 真库接入，玩具模型（2D 高斯）后验正确 | 解析解对比 |
| M4 | 参考物理模型上与 MCMC 后验一致 | KS 检验 + 图 |
| M5 | 配置条目 + 失败路径测试 + 文档同步 | strict-build + pytest |

注意 M1 是全序列最难的未知数，排最前；M2 物理上无意义但把**集成风险**
和**算法风险**拆开了——之后任何失败都能立刻归因于其中一侧。

**第 3 步 · 固化**：完成后提取的规则可能是——"外部采样库一律先用假
似然 spike 验证调用模式，再谈接入"。写进 CLAUDE.md，下次直接受益。

## 5. 卡住时的急救顺序

1. **换高度**（30 分钟规则）：代码层卡住升方案层，方案层卡住升目标层。
2. **重述问题**：向一个想象中的同事把问题讲一遍（费曼式）；讲不通的
   那一句就是你没懂的那一块。
3. **查假设台账**：从 `assumed` 堆里挑"最致命且最没验证过"的那条去验证。
4. **缩小复现**：能删一半还复现就删一半，直到假设无处可藏。
5. **撤退也是选项**：revert 到上一个绿点换路径，好过在错误路径上加班。
   沉没成本不是理由，是病症。
