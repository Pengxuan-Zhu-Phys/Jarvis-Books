# 05 · 训练计划：把方法练成本能

> 原则只有一条，来自刻意练习研究：**单一技能 × 即时反馈 × 略超当前能力**。
> 反过来说：一次练一堆、没有记录、全在舒适区——那叫工作，不叫训练。
> 本篇是五步法第 5 步（自动化）应用于你自己：先手动跑通方法（01–04），
> 再把它固化成不耗意志力的习惯。

## 1. 五个日常 Drill

### Drill A · 预测练习（校准直觉，性价比之王）

- **做法**：每次运行任何东西（测试、构建、脚本、扫描）之前，写一行预测。
  "这次 pytest 全绿" / "这个改动会让输出的 Ω h² 变化 <1%" / "编译会在
  链接期报 complex 冲突"。运行后标 ✓/✗。
- **频率**：每天所有运行。单条成本 <10 秒。
- **记录**：Notion database 一行一条：`日期 / 预测 / 实际 / 命中`。
- **进步指标**：月度命中率上升；更重要的是 ✗ 的类型变化——从"完全没
  想到"变成"方向对了幅度错了"。
- **原理**：预测错误是唯一无法自欺的信号。不写下来，大脑会在事后把
  任何结果都追认成"跟我想的差不多"。

### Drill B · 假设台账（调试纪律）

- **做法**：调试时立一条硬规则——**写下假设（含机制）和判别实验之前，
  不许改任何代码**。格式：`假设 X 因为机制 Z → 探针：<最便宜的判别实验>
  → 结果：排除/确认`。
- **频率**：每次调试，无例外。
- **进步指标**：每个 bug 消耗的假设数下降；"无机制的猜测"（写不出
  "因为"的条目）趋近于零。
- **原理**：见 [01-the-loop.md](01-the-loop.md) Phase 3。台账防的是
  调试的头号杀手——绕圈（同一个猜测换装重试三遍）。

### Drill C · 20 分钟侦察（读新代码）

- **做法**：任何新代码库/新模块，先按 [04](04-learning-codebases.md) §3
  的九问侦察卡计时侦察，再开始正式阅读。
- **频率**：每逢新包/新模块；无新对象时，拿自己三个月没碰的旧代码练
  （效果惊人地一致——它已经是陌生代码了）。
- **进步指标**：20 分钟内答满九问的比例；第 9 问（意外）越来越少——
  说明你的先验越来越准。

### Drill D · 费曼一页纸（检验理解）

- **做法**：每个学习/攻坚会话结束时，给想象中的新人写一页解释。写卡住
  的地方**用红字标出**（Notion 里用高亮）——那就是明天的第一个问题。
- **频率**：每个深度会话收尾，15 分钟封顶。
- **进步指标**：红字越来越少；旧的一页纸半年后重读仍然成立。

### Drill E · 需求验尸（五步法第 1、2 步的日常化）

- **做法**：每周挑一个进行中的任务，对它的每条需求写三栏：
  `主人（人名）/ 想达成什么 / 不做会怎样`。然后强制挑出**一条**
  删除或降级。
- **频率**：每周一次，30 分钟。
- **进步指标**：加回率——被你删掉后来又加回来的比例。**长期为 0% 说明
  删得太保守，>30% 说明删得太草率，10% 上下是健康区。**

## 2. 节奏

| 周期 | 动作 |
|------|------|
| 每天 | Drill A 顺手做；调试即 Drill B |
| 每个深度会话 | 收尾 Drill D 一页纸 |
| 每周（30 分钟） | Drill E 需求验尸；翻一遍本周预测记录的 ✗ 条目，找模式 |
| 每月（1 小时） | 复盘四个指标（§4）；把稳定的经验升格为 general rule；删掉失效的旧规则——**规则库也要跑五步法** |

## 3. Notion 搭建建议

- **三个 database**：
  1. `预测记录`（Drill A）：日期 / 预测 / 实际 / 命中 / 类别（测试·构建·物理数值·其他）
  2. `假设台账`（Drill B）：问题 / 假设 / 机制 / 探针 / 结果 / 最终根因
  3. `练习卡片`：任务卡（[03](03-complex-code-tasks.md) §1）、侦察卡
     （[04](04-learning-codebases.md) §3）、三天上手计划（04 §7）各设为
     **Template**，一次点击新建
- **一个页面** `规则库`：存放所有 general rule，每条一行 + 来源链接。
  这就是你个人的 CLAUDE.md——事实上，它应该定期同步**进**各仓库的
  CLAUDE.md，人与 AI 共用同一套判断。
- 别过度装修。**database 超过三个、字段超过五个，就是在给玻纤垫子造
  机器人**（[02](02-musk-five-steps.md) §6：方法验证有效之前不自动化）。

## 4. 进步度量（月度看这四个数）

| 指标 | 定义 | 期望走向 |
|------|------|---------|
| 预测命中率 | Drill A 月度 ✓ 比例 | 上升后趋稳（趋稳后要主动挑更难的预测，否则是在舒适区刷分） |
| 假设效率 | 每个 bug 消耗的假设条数 | 下降 |
| 上手速度 | 新包从零到 trifecta 三命令跑通的时间 | 下降 |
| 开工合格率 | 动手前填了任务卡（完成态+边界+危险假设）的任务占比 | → 100% |

## 5. 90 天路线

| 阶段 | 重点 | 判定进入下一阶段 |
|------|------|----------------|
| 第 1–2 周 | 只练 Drill A + B（最小组合，先建立"记录-反馈"的肌肉） | 连续 10 个工作日无遗漏 |
| 第 3–6 周 | 加入 Drill C + D；开始用任务卡开工 | 侦察卡 20 分钟内答满九问 ≥3 次 |
| 第 7–10 周 | 加入 Drill E；月度复盘跑起来 | 完成两次月度复盘，规则库 ≥15 条 |
| 第 11–13 周 | 撤脚手架：任务卡和侦察卡**不看模板**凭本能填，填完对照模板查漏 | 查漏无缺项 → 方法已内化 |

第 13 周之后，这套文档的正确状态是**很少被打开**——就像你现在不会打开
"如何骑自行车"。届时唯一保留的例行动作是月度复盘和规则库维护。

## 6. 与本文件夹其他部分的关系

- 你练的这套回路，和 [../model-guides/](../model-guides/README.md) 里给
  模型立的规矩，是**同一套判断力的两个投影**：你的`规则库`对应模型的
  CLAUDE.md；你的 Drill D 一页纸对应模型的 learnings 笔记；你的需求验尸
  对应模型的升级门。人与工具共享标准层，两边的每一次进步都互相复利。
- 终极检验（也是一开始的承诺）：**面对复杂代码任务，更快且更准**——
  快来自删除（读得少、试得便宜），准来自校准（预测练习）和纪律
  （假设台账）。快和准不是权衡关系，它们都是同一个东西的产出：
  **在正确的问题上，用最小的实验，获取最大的信息。**
